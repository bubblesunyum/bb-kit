Rejected, but it still tempts: giving SearchField an Escape-to-clear
handler. WebKit does it natively on type="search" and it feels missing.
Left out because Escape without stopPropagation would clear the field *and*
close whatever dialog the field sits in, and stopping propagation breaks the
dialog instead. Both are worse than no handler. If FilterBar ever lives in a
dialog this needs a real answer rather than a reflex.

The clear button is worth knowing about before extending the component: it
unmounts itself when it clears, so anything focus-related around it is
fragile. Focus is put back on the input by a ref on the *wrapper*, not the
input, because the input takes the caller's props and a caller's own ref
among them. Do not "simplify" that to a ref on the input.
